Send your first ping

Send JSON to POST /api/pings. Everyone on the map can see your ping. Run the curl example against the local development server, or change its URL to the hosted site. Run the JavaScript example in this page’s browser console.

What to send

Field Type Limit
latitude number −90 to 90, inclusive
longitude number −180 to 180, inclusive
title string 1–80 characters after trim
message string 1–160 characters after trim
imageUrl string, optional HTTPS URL, up to 2,048 characters; no credentials

Send numbers as JSON numbers. Zero is valid. Text limits count Unicode code points. The entire UTF-8 body must be 4 KiB or smaller.

Text appears as plain text. Supply a small image that its host allows other sites to display. Hello World loads it when someone opens the card. The image host receives that request; Hello World does not upload, resize, or store the image.

What comes back

A successful request returns 201 Created with your ping: 

{
  "latitude": 37.7749,
  "longitude": -122.4194,
  "title": "Hello from San Francisco",
  "message": "We just shipped our first project.",
  "id": "f71a71d0-bafa-408e-b908-319d70678cf0",
  "createdAt": 1789056000000,
  "expiresAt": 1789056060000
}

Times use Unix milliseconds. The server adds id, createdAt, and expiresAt. It includes imageUrl when you supply one.

A new ping pulses for two seconds. Its dot stays for 60 seconds in total. Hover, focus, or tap the dot to read its card. Refreshes do not extend that time.

Room for everyone. Limits for each source.

The API accepts one ping every 5 seconds across API callers, and one every 60 seconds per source address. The browser form allows one every 10 seconds per address. Both paths share a map limit of one ping per second and the daily cap. There is no queue or automatic retry.

The map blocks repeated title-and-message pairs for five minutes, across all addresses and both paths. The check ignores case, differences in whitespace, and equivalent Unicode forms. Changes to coordinates or image URLs do not bypass it. A rejection does not extend the wait.

/api/pings always uses API limits. The form uses a separate route that requires same-origin browser headers. Scripts can imitate those headers; this distinction does not prove a human sent the request.

The initial daily limit is 10,000 accepted pings. It resets at midnight UTC. Invalid requests do not consume an acceptance slot. Live connections have a separate cap of 100 viewers. 

HTTP/1.1 429 Too Many Requests
Retry-After: 5

{
  "error": {
    "code": "api_rate_limited",
    "message": "The API accepts one ping every 5 seconds. Try again later.",
    "retryAfterMs": 4742
  }
}

On 429, wait at least the number of seconds in Retry-After. Add a small random delay before you retry. Another caller can take the next slot. Avoid retry loops; use a small retry count.

For source_limited, Retry-After counts down the 60 seconds since the last accepted ping from your address. For api_rate_limited, it counts down the five-second API interval. For rate_limited, it counts down the shared one-second interval. For duplicate_content, it counts down the five-minute duplicate interval. For daily_limit, Retry-After points to midnight UTC. A network failure does not prove rejection: the server can accept a ping before the response reaches you.

Status Meaning

405 Wrong HTTP method
413 Body exceeds 4 KiB
415 Content type is not application/json
429 Rate limit, duplicate content, or daily cap

Application errors use { "error": { "code": "…", "message": "…" } }. Cloudflare can return its own error page when its free quota runs out. The map shell and this guide remain static.

Read the ping history

Search the last 3,600 pings, newest first. A ping leaves the map after 60 seconds. It stays in the public log until 3,600 newer pings replace it.

Send GET /api/history?q=hello&limit=50. The response contains { pings, total, next, serverTime }. Each ping has the same fields as the submission response. total counts all current matches, before pagination. serverTime uses Unix milliseconds.

Send the next cursor as before, with the same query, to read older matches. A null cursor means no older matches remain. New pings do not repeat rows on older pages. The retention limit can remove rows between requests.

q accepts up to 240 Unicode code points. Search ignores case, whitespace differences, and equivalent Unicode forms. Every word must appear in the title or message. Search matches inside words.

limit defaults to 50 and accepts integers from 1 through 200. before accepts a positive integer cursor. Invalid, unknown, or repeated parameters return 400 invalid_query.

The endpoint supports public CORS with GET, HEAD, OPTIONS. Responses use Cache-Control: no-store. History starts empty on the first deployment. Reload the history page to see newer pings.

A shared, public space

Everyone shares the same map and public history. There are no accounts. Ping text stays public until 3,600 newer pings replace it. Other viewers can copy what they see. External image hosts still receive image requests. Do not send anything private.

The API supports Cross-Origin Resource Sharing (CORS) without credentials, so a script on any site can send a ping. Preflight requests do not consume the shared acceptance slot.

This project runs on a free service with finite quotas. Rejected requests still use quota. The map can stop accepting pings or live connections until the quota resets.
